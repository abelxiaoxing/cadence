## Project index

- `openspec/` contains the target root's OpenSpec core.
- `openspec/config.yaml` selects the spec-driven schema.
- The root is the standalone `@abelxiaoxing/cadence` package: manifest `package.json`, lockfile `bun.lock`, private extension `src/index.ts`, and immutable professional Agents under `agents/`.
- Prompt entrypoints: `prompts/abel-init.md`, `prompts/abel-design.md`, `prompts/abel-implement.md`, and `prompts/abel-diagnose.md`.
- Shared workflow: `skills/abel-workflow/SKILL.md` is authoritative for Gates, receipts/hashes, traceability, Red-Green-Refactor, AGENTS maintenance, and parent/worker boundaries.
- Configuration and HTTP boundary: `skills/_shared/load-config.mjs` with `skills/_shared/load-config.d.mts`, `src/subagent-endpoint.ts`, `skills/_shared/http-client.mjs`, and `config/.env.example` own whole-file cadence env parsing, per-role endpoint resolution, and HTTP configuration.
- Research skills: `skills/context7-auto-research/` and `skills/grok-search/`; commit skill: `skills/git-commit/`.
- Child execution: `src/child-session.ts` owns isolated in-memory sessions and separate stable-task/phase-request submission identity while forwarding tool/Scheduler cancellation across session creation, prompt, and disposal; `src/scoped-tools.ts` confines read/grep/find/ls to declared read/write paths within approved roots; `src/empty-resource-loader.ts` supplies no discovered resources; `src/parent-payload-bridge.ts` owns generation/model-bound parent callback capture, native-carrier recognition, idempotent wrapper install, unwrapped delegation, FIFO composition, lifecycle invalidation, and final Responses normalization; `src/parent-provider.ts` owns abortable inherited phase-local auth/capture composition and standalone custom endpoint Providers with retries disabled; `src/worker.ts` owns the process-local canonical-root/change/task-keyed TaskRecord registry, its immutable admitted TaskBoundary, pinned execution and Subagent endpoint identity, derived conflict declaration, and closed phase/budget/checkpoint/terminal state.
- Scheduling: `src/scheduler.ts` owns bounded FIFO DAG-ready attempt admission, pure declared conflict/resource/verification-lock serialization, and per-batch/all-batch cancellation with settlement; it retains no cross-call task state. `src/runtime.ts` admits each Implement TaskBoundary once, immediately defers task-lifetime conflicts against nonterminal records before registration or scheduling, resolves later phase attempts against the stored TaskRecord, derives child envelopes from the stored phase boundary, binds each Pi tool signal only to its run batch, shares two non-cancelled launches across artifact/stale/transport failures, advances phases only after exact parent apply, bounds the independent AGENTS checkpoint, replays terminal facts without work, requires complete safe phase snapshots, and serializes parent applies through a process-local FIFO; `src/file-snapshot.ts` owns bound/currentness helpers. `src/drain.ts` owns unified idempotent cleanup after Scheduler and parent-apply settlement (admission closed, bridge/results/TaskRecords erased, only dispatcher activation removed); lifecycle state stays in memory only.
- TUI presentation: `src/subagent-activity.ts` owns the process-local interactive Subagent activity controller, width-safe inline/widget rendering, compact terminal metadata, and the non-TUI boundary; active display/timer state is never persisted.
- Structural delivery: `src/submit-tool.ts` accepts one final typed result; `src/result-store.ts` retains exact diff bytes and sealed stage/root/change/task/origin/phase/launch/write/dependency/snapshot facts only in memory; `src/verification-capability.ts` is the shared Design/Implement consumer capability validator for structured Vitest, package-script, static, and ordered-step contracts; `src/candidate-preflight.ts` owns parent-only strict/current isolated verification with private bundle-based sibling reconstruction, kind-directed execution, Bubblewrap isolation, typed rejection, unknown-error propagation after deterministic cleanup, and unchanged dependency policy; `src/patch.ts` preserves those typed failures through exact ordinary Git screening/application and managed-only AGENTS checkpoints; child code never imports either parent boundary; `src/contracts.ts` owns structured verification admission, closed failure codes, strict apply/discard/checkpoint operations, strict Design/Diagnose envelopes, the one-time Implement open-task or phase-attempt boundary contract, and complete ordinary textual unified-diff admission.
