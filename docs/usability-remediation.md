# 可用性修复方案

## 目标与边界

本次为普通工程修复，不激活 Abel stage。
保留单一状态转换权威、候选工作区、验证和可恢复应用。
默认仍使用隔离执行；本地可信执行只能由宿主显式选择，不静默回退。
不修改包内不可变 Agents。

## 实施顺序

1. 验证反馈：保留有界、可读的错误摘要，供后续 Worker 修复使用；将错误身份与诊断分开。
   对无法结构化归因的普通命令避免把不完整日志当作旧失败证明。
2. 环境兼容：支持仓库内 workspace 链接；提供显式本地可信执行配置和集中环境检查，提示平台、工具与配置问题。
3. 模型执行：按模型窗口预留上下文预算，提前停止无效请求；分类 Provider 错误；提供宿主可配置请求预算。
4. 验证性能：合并并发环境身份读取，保留验证后的完整复核；增加依赖扫描基准与指标，不用不可靠缓存替代 currentness。
5. 小任务作者入口：提供代码生成的单任务草稿模板，不推测验收、测试证据或权限；继续使用原编译器验证。
6. 产品运维：前置快速开始、兼容性和排障文档；提供只读任务/存储概览，不自动清理可恢复数据。
7. 评估：增加显式启用的真实模型评估矩阵和机器可读汇总，区分预检与真实完成，不在普通 CI 中隐式调用付费模型。

## 验收

- 对时间戳扰动、长 stdout 遮挡 stderr、workspace 链接增加回归测试。
- 检查失败摘要能抵达下一次候选请求，而不仅存在于底层返回值。
- 验证可信执行的正常退出、取消、超时、报告路径和配置选择；严格模式不自动降级。
- 验证上下文预算在请求之前生效，错误分类不把上下文问题当作端点故障重试。
- 检查新增作者入口仍经过完整 PlanDraft 编译。
- 执行 check、lint、全部测试、pack、traceability、真实 OpenSpec 和 Bubblewrap 集成。
- 真实模型完成率及大型 consumer 性能改善以实际测量为准，未运行不宣称通过。

## 实施结果

- 已完成：有界验证诊断、当前操作后续 Worker 反馈和 Provider 错误分类。

- 已完成：仓库内普通/带 scope 的 workspace 链接映射；显式 `local-trusted` Linux 执行、环境变量名配置、PID namespace 后代取消和超时。
- 已完成：模型窗口感知的请求前预算和输出预留；首响应/空闲/验证时限可配置。
- 已完成：I/O 尚未开始的同批依赖身份扫描合并，后置检查拒绝旧在途扫描，最后订阅者取消后等待 I/O 退出，不缓存已完成证据。
- 已完成：`singleTask` 精简作者入口、完整编译检查和派生来源摘要。
- 已完成：预构建且可在 node_modules 内运行的 `doctor` / `runs` 命令、快速开始与可信模式文档。
- 已完成：三个门禁场景与独立缺能力观察的评估矩阵、重复次数、机器可读汇总和手动真实模型 CI 入口。

## 仍需后续量化或另行扩展的范围

- 缺能力场景单独作为非门禁观察结果，不计入产品任务完成率；不能将任意停滞算作恢复验收通过。
- 没有运行付费真实模型评估，不能宣称模型完成率、成本或端到端延迟已改善；手动评估入口已准备。
- 可信执行要求 Linux Bubblewrap 的 PID namespace；原生 macOS/Windows 不回退执行，Windows 可使用 WSL。
- 不自动安装新依赖或启动数据库/浏览器服务，不提供不可靠的宿主缓存复用。
- 未新增 Jest/JUnit/Node test 的结构化报告适配器；通用命令保持明确的归因不确定状态，而不是虚构断言身份。
- 不压缩/改写模型证据，不用已完成扫描缓存替代验证前后 currentness；可信模式的大依赖副本准备和清理已迁入可取消 I/O Worker，但仍有磁盘复制成本。
- 未新增多制品原子批量写入协议；小任务通过精简作者结构减少重复字段，原有制品租约和逐文件幂等写入保持不变。
- 不为缩短文件而拆散状态权威；本次新增诊断、预算、作者扩展和运维逻辑均位于独立模块。

## 提交前复审修复

1. 扫描只合并开始读取前的订阅者；回归测试覆盖验证期间依赖变化后提交复核，不再读取旧观测。
2. 可信执行仍使用 Bubblewrap PID namespace（共享网络和文件系统），取消会终止 detached 后代；缺少 backend 则暂停。
3. oracle 使用独立副本，同一 profile 同时控制环境和执行后端；无模型集成测试覆盖两种模式的正确/错误产品字节。
4. 默认矩阵仅包含三项有成功 oracle 的门禁；缺能力观察为单独非门禁 job，失败不阻塞正常发布评估。
5. 依赖视图准备、删除和复制迁入 I/O Worker，逐项取消检查；父线程保持响应，并在取消和失败后等待 worker 退出再清理 scratch。
