# Subagent 提交协议减负

## 目标与边界

减少模型仅因填表或遗漏提交工具而丢失已经完成的调查，同时保留严格的内部结果与执行权限。
本次修改不引入自由文本自动采纳、不扩大读写权限、不修改审批和验证权威，也不增加无限重试。

## 实施方案

1. 在 `src/evidence-draft.ts` 分离模型填写与内部结果。
   Design 保留七个必填字段：`module_name`、`scope`、`files_read`、`evidence`、`constraints_discovered`、`open_questions`、`risks`。
   代码补齐省略的身份与提示性字段，显式错误值和未知字段继续被拒绝。
   Compact evidence 同样允许省略身份、dependencies 和 hints。
   补齐的提示性字段只表示未提供建议，不能证明不存在影响或授予权限。
2. 对齐 evidence schema 的路径、唯一集合、身份常量和 impact 枚举。
   严格内部 `validateEvidenceResult` 不接受草稿；工具完成草稿后仍须通过它。
   行号先后等跨字段约束由内部校验保留，并反馈具体字段。
3. 改善证据和 replace 诊断。
   返回引用索引、字段、允许值，区分 replace 的未匹配、多处匹配、文件缺失和未授权路径。
   自定义诊断不回显 claim、源码、替换内容或未知字段名。
   路径反馈只包含有界、安全的相对路径。
4. 在 `src/child-session.ts` 增加一次同会话补交提醒。
   仅在正常 text-only stop、从未发出结构化提交、没有既有失败时触发。
   沿用原会话、工具、取消、时限和用量统计；不从文字推断有效结果。
   错误、截断、取消、已拒绝提交和已接受提交均不触发提醒。
   提醒要求不重复调查；运行时不增加工具权限，但不保证模型不会继续使用已有只读工具。
5. 会话分类计入 Pi 在 execute 前拒绝的工具调用。
   两次结构化提交的原有截止规则保持不变，避免将 SDK schema 拒绝误报为从未提交。
6. 对齐三个专业 Agent 的说明，并更新其 provenance 哈希、包成员清单和生成的 workspace I/O worker。

## 验证

先添加回归测试，改动前观察到六项失败，然后实施修复。
新增测试覆盖精简草稿的 SDK 接收、内部严格合同、显式错误身份、遗漏关键事实、错误枚举、路径 schema 与 validator 对照、诊断内容边界、一次补交、补交期间取消和原时限、截断不补交及 SDK 拒绝计数。
既有测试继续覆盖重复终态拒绝、一次提交纠错、只读批次、产物封存、路径隔离和 OpenAI Responses 协议。

完整 `bun run verify` 通过：793 项测试通过，14 项条件跳过，真实打包的 75 个成员匹配清单。
这证明确定性测试中的行为，不代表已测得真实模型的成功率提升。
本次未进行外部模型基准、Google Provider 实测或社区实现的在线对照。
