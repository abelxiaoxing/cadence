# Design 草稿构造边界重设计

本次把可由现有声明唯一推导的字段移到编译器，减少模型重复填写、出错后再查源码的往返。
改动集中在草稿输入与错误反馈，执行计划仍经过原有的完整校验。

## 依据与目标

[上一轮真实评估](optimization-live-evaluation.md)中，单任务约第 519 秒才完成 Design；多任务修正测试归属后，又因验证输入绑定不匹配返工。
这些错误来自重复描述同一事实：验证契约已经指定输入，任务写入声明已经指定测试的编辑者。
因此优先消除重复填写，而不是增加重试、放宽验证或缩短模型的思考时间。

## 输入与执行计划的分界

`PlanDraft` 接受精简的作者输入；`ImplementPlan` 保留完整规范结构。
编译器只补全缺失字段，然后交给原有的规范化、图就绪和能力校验。

| 可省略字段                             | 推导依据                                                                                     | 不唯一或显式错误时                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `tracking`                             | 当前任务 ID 与固定的父会话跟踪策略                                                           | 显式块必须符合原有策略                     |
| 阶段 `verificationInputs`              | 验证契约要求的路径；唯一声明的 output 优先，否则绑定工作区文件                               | 多 producer 拒绝；显式错误绑定拒绝         |
| 测试 `disposition`、`regressionTaskId` | 本任务编辑为 `current-task`；其他唯一任务编辑为 `regression-task`；无任务编辑为 `unaffected` | 多个其他编辑者需要明确选择；显式标签仍校验 |

测试路径和调查证据仍由作者填写。
推导不会添加读写权限、输出声明或任务依赖，也不会生成验证命令或批准需求。
绑定到工作区的文件仍须存在且是安全的普通文件；output 的生产阶段与依赖顺序仍须满足原有约束。
机械修改和重构任务沿用只读 Red 的既有规则，不把被忽略的 Red 写入声明计作测试归属。

完整计划的解析不执行补全，因此缺字段的存储计划仍被拒绝。
精简草稿与等价的显式草稿生成相同规范字节，草稿本身不被修改；现有完整计划的身份也保留。

## 反馈与可发现性

图结构检查在一次调用中收集独立任务和 output 的错误，再整体拒绝该图。
每个无效任务或 output 返回其首个结构错误；这不承诺一次枚举所有校验层的所有问题。
输入绑定不匹配与测试归属错误提供字段位置和期望、实际路径，模型可以直接修正对应边界。

工具反馈和展开后的终端显示共用 `src/design-diagnostics.ts` 的纯投影函数。
它只保留允许的标识和相对路径，单个路径列表最多 32 项，并标记截断；修正提示由代码生成。
原始异常、任意调用者提示和 Provider 内容不会进入反馈。
提示和工具参数直接指出已安装示例的路径，示例实际省略这些可推导字段，并由编译器集成测试验证。

## 复杂度与验证

实现复用现有验证输入提取和图校验，没有增加服务、持久化结构、工作流状态或新的计划语言。
保留显式的范围、验证契约和恢复预算，避免以方便构造为由引入隐含执行权限。

新增 7 项行为测试覆盖等价编译、严格读取、输入不变性、producer 歧义与时序、测试归属、批量诊断、反馈边界，以及真实工具的失败—修正—预检往返。
复用已有的规范身份、执行图、终端和隔离测试；未新增提示词措辞测试或大面积快照测试。

- `bun run verify`：745 项通过，14 项条件跳过，发布包 74 个成员匹配清单。
- `bun run traceability:check`：64 项活动 Requirement/Scenario 引用各有唯一归属。
- `bun run check:agents`：项目索引有效。
- 启用真实 Linux 隔离后的既有隔离与工作区 I/O 检查：14 项通过。

模型端收益以相同需求和 600,000 ms 上限的真实评估判断；自动化检查通过不等于端到端耗时已经改善。
最新 gpt-6-astra 和用户切换后的 LocalModel 多任务均在计划提交前达到截止，因此尚未验证本次字段推导在模型端的收益。
[进一步的时间分解与本地超时复现](multiple-task-timeout-diagnosis.md)定位到父模型响应和调查构造步骤，而非计划校验计算。
真实评估结束后，修正了诊断投影中传入 `pathsTruncated: false` 覆盖真实截断标记的问题，复用原有反馈边界测试覆盖。
