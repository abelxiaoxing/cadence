## 已证实的行为与限制

- **重启后的交付发现有效。**
  Design 完成后，评估器关闭原宿主，再以新会话调用 Implement。
  新宿主完成实现及应用，控制面外的 Bubblewrap oracle 验证 `add(2,3) === 5`。
  该次运行没有工具失败或宿主模型错误，无需再次批准。
- **控制面完成与评估通过必须区分。**
  10 分钟的单任务运行约在第 497 秒完成 Design，第 592 秒返回 Implement 完成。
  评估器仍在等待父会话结束时触发截止时间，尚未运行 oracle，因此 `completed: true` 与 `success: false` 同时成立。
  延长窗口的复测被 Provider 错误中断，未补得该场景的独立验收结果。
- **多任务计划仍有构造成本。**
  首次预检返回 `invalid-implement-graph` / `current-task-outside-write-set`。
  模型随后读取源码，但在截止前未提交新的预检；最终快照无编译计划、无证据事实，产品文件未改变。
  当前结果未覆盖多任务实际执行和合并，不能据此判定调度器失败或成功。
- **缺失能力场景尚无有效结论。**
  模型保留了审批、决策、证据和部分设计产物，抽样时产品文件未改变。
  Provider 在设计阶段中断，既未验证明确的能力阻塞，也未验证补齐能力后的恢复。
  临时项目在评估结束后由评估器清理；抽样快照仅证明清理前曾有这些持久事实。
- **Provider 恢复了调用能力，稳定性未获证明。**
  前四次有效尝试均无宿主模型错误，后两次各发生四次 `provider` 类错误。
  脱敏分类不足以区分限流、服务内部错误或其他 Provider 原因，不进一步猜测。

## 接口改进方向

10 分钟单任务和多任务分别有 17 次 Cadence 源码读取/检索；成功的重启场景也有 8 次。
`src/index.ts` 的 Gate A `contract` 只暴露宽泛的字符串或对象类型，完整校验形状分布在 ChangeContract、计划及验证契约代码中。
Design 提示列出了字段和职责，但没有完整的最小 PlanDraft 示例。
这些证据提示结构化契约的可发现性值得优先改善，尚不足以证明它解释了全部延迟。

后续可先提供与现有校验器一起验证的最小 ChangeContract / PlanDraft 示例，并从 Design 提示直接引用。
沿用现有编译器、诊断和权限边界，不增加新的工作流层。
用相同模型、相同时间上限重复单任务和多任务，观察源码读取次数、首次预检通过率与端到端耗时。
本轮未同时修改产品提示，以保留当前版本的复评依据。

## 本轮评估器修复

早期两次尝试在截止时暴露 `ERR_STREAM_WRITE_AFTER_END`：超时分支先关闭 stdin，被 abort 唤醒的另一分支随后请求统计。
这属于评估器生命周期竞争，未能生成有效报告；它们单独记录为无效尝试，不计入上表。

修复将 RPC 请求绑定到具体宿主，处理输入流关闭及待处理请求，串行化宿主关闭，并等待竞争分支退出后才清理项目。
每个宿主只在关闭前采集一次统计，覆盖超时与重启，避免重复计数。
三个回归分别覆盖 Design 超时、Implement 超时和重启后的 Implement 超时；修复前均失败，修复后通过。

`bun run verify` 通过：726 项测试通过、14 项条件跳过，类型/语法、格式和 72 成员真实打包检查通过。
其中评估测试共 11 项通过。
