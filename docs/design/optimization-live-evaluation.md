## 对照与瓶颈

- 单任务此前一次完整成功耗时 9:25，本次约慢 22 秒；此前同为 10 分钟窗口的运行虽完成控制面实现，却未赶上独立验收。
  本次成功说明当前路径可用，不构成速度提升证据。
- 历史单任务和多任务对照各查阅 Cadence 源码 17 次，本次分别为 7 次和 10 次，补充说明后的多任务为 5 次。
  新示例被实际使用，源码查阅减少；模型随机性、服务时延及历史并发条件使单次对照不足以证明因果关系。
- 本次单任务约在第 519 秒完成 Design，Implement 控制调用在第 539–570 秒运行，最后在第 587 秒完成独立验收。
  主要耗时集中在 Design 及父会话交接；六次工具失败分别为两次读取、一次查找、一次 Gate A 请求校验、一次计划预检和一次最终交付校验。
  这六次工具失败不是六次 Provider 故障。
- 多任务补充说明后约在第 583 秒完成 Design，评估器仍在等待父会话结束时达到截止时间，因此尚未发送 Implement 命令。
  该次不能用于判断多任务执行、调度或合并是否成功。

## 已复现的问题与小幅修正

多任务首次运行在第 514 秒返回 `invalid-implement-graph` / `current-task-outside-write-set`，与历史多任务尝试相同。
在原评估继续运行时，只读加载当时的草稿并调用同一编译器，复现了该诊断：两项任务都把仅声明读取、没有声明写入的现有测试标成 `current-task`。
没有向模型补充草稿、修正内容或新的审批。

在 [Design 提示](../../prompts/abel-design.md) 中增加三行说明：

- `current-task` 表示当前任务会修改该测试，路径必须属于某个阶段的 `write` 集合。
- 其他任务负责修改时使用 `regression-task` 和对应任务 ID；保留而不修改的现有测试使用有证据支持的 `unaffected`，仍可包含在 `affectedSuite` 中。
- 不应为了满足标签而扩大写入权限。

没有修改验证器、存储结构、写入权限或恢复预算，也没有新增测试文件。
提示变更通过现有提示加载、可执行示例与分发测试，共 15 项通过。

复测第 407 秒的首次预检未再出现测试归属错误，但返回了四项 `verification-input-binding-mismatch`。
只读复核确认原有归属错误已消失，新的错误涉及两项任务的 Red/Green 验证输入绑定；校验器要求绑定路径与验证契约要求的路径集合一致。
模型自行改写草稿后，第 517 秒预检通过，第 541 秒编译通过，第 583 秒交付最终校验通过。
补充说明后的这次计划已避开原错误；验证输入的填写与修正仍有成本。

## Provider 与超时口径

三次均为 `modelErrors: 0`、`autoRetries: 0`，没有 SDK 超时诊断。
观测到 103 个 Provider 请求和 102 个 HTTP 响应，响应状态全部为 200；一个请求在取消前没有收到响应头。
两次多任务截止时各记录到一次请求错误事件，均紧邻评估器取消和 assistant `aborted`，底层错误码未识别。
保留这两次事件，不将它们标成 SDK `Request timed out` 或已确认的服务端故障。

HTTP 200 不保证完整流式响应成功，所以只有独立 oracle 通过的单任务记为完成。
本次结果不证明 Provider 永久稳定，也不能追溯确定历史 Provider 错误的根因。
`evaluation-deadline` 是整轮任务的时间预算耗尽，与单个 SDK 请求超时不同。
