# Provider 错误分析与复测：2026-09-07

本轮未复现真实 Provider 故障，单任务已通过完整独立验收。
已确定并修复的是诊断误分类：旧评估器会把 SDK 的连接超时文字归入 `provider`。
上次记录没有 HTTP 状态或原始 SDK 错误，不能据此确定历史故障究竟发生在网络、网关还是模型服务。

## 确定的问题

旧分类器只识别 `timeout | connect | fetch | network` 等字样。
本机 OpenAI SDK 6.40.0 在识别到连接超时后，会抛出 `APIConnectionTimeoutError`，显示文字为 `Request timed out.`。
这句话没有命中旧表达式，因而被归入笼统的 `provider`。
提前结束的响应流也可能被归入同一类别。

本轮通过替换 SDK 的 fetch、注入连接超时，确定性复现了这一条路径：没有真实网络调用，旧分类为 `provider`，修复后为 `transport`，细分类为 `timeout`。
这证明标签存在误导性，**不证明上次故障一定就是连接超时**。

Pi 默认允许首次调用失败后再自动重试三次，退避时间为 2、4、8 秒；Provider SDK 层默认不重试。
因此，同一组出现四条模型错误可能对应一个逻辑请求的四次尝试，不能直接解释为四次独立服务故障。
上次没有记录重试事件，无法逐条确认这一对应关系。

## 真实复测结果

先用不加载 Cadence、关闭自动重试的真实 Pi RPC 做基线，再单独运行完整任务，最后做并发探测。
探测只要求返回 `OK`；长上下文使用不含业务数据的合成填充，每个请求 182,600 个填充字符，宿主报告 33,425 token。
没有修改默认模型、凭据、全局重试配置或任务验收条件。

| 检查                           | 结果                    | 耗时 / 规模                |
| ------------------------------ | ----------------------- | -------------------------- |
| gpt/gpt-6-astra 串行短请求     | 2/2 成功                | 7.4 秒、4.1 秒             |
| gpt/gpt-6-astra 完整 small-fix | **通过独立隔离验收**    | 9 分 25 秒，47 个 HTTP 200 |
| gpt/gpt-6-astra 四并发短请求   | 4/4 成功，均为 HTTP 200 | 每个 3.1–5.4 秒            |

总共直接观测到 57 个 HTTP 响应，全部为 200，没有观测到网络请求错误事件。
首次短请求发生在有效 HTTP 观测启用前，仅保留了 RPC 成功结果，其状态码未知，不计入 57 个响应。
完整工作流没有宿主模型错误或自动重试，包含一次文件读取工具错误，之后仍完成了设计、实现及独立验收。
HTTP 200 本身不保证流式响应成功，因此完整任务另以 oracle 通过作为成功依据。

完整工作流观测到的最大请求载荷为 210,230 字节，说明当前配置可以处理该任务的工具和长上下文。
配置的 thinking level 为 `xhigh`，实际观测到父请求使用 `high`、子请求使用 `medium`；配置值不等于线上请求参数。

## 如何解释上次错误

- **持续性的凭据或基本协议错误，目前没有证据支持。**
  两个 Provider 的短请求成功，gpt 的完整任务也成功。
  这不追溯证明历史凭据或服务状态始终正常。
- **固定的四请求并发上限、约 180 KB 输入限制，本轮未触发。**
  短请求和合成长请求的四并发均成功。
  这只是有界突发探测，不能排除过去的瞬时限流、按 token 计费的限额或长时间高负载问题。
- **临时连接超时、响应流中断或网关/服务错误仍是候选原因。**
  旧分类会混合这些情况，现有历史证据不足以选择其中一个。
  此前“Provider 有间歇性错误”应理解为客户端的粗分类观测，不能当作已经定位到服务端的根因结论。
- **历史根因仍需故障当时的证据。**
  本轮没有服务端日志，旧记录也不能补回当时未保存的状态码。
  不将本次未复现解释为永久恢复，也不修改全局重试或降低验收来掩盖失败。

## 已实施的诊断改进

`scripts/workflow-evaluation.mjs` 现在保留最多 16 条 `modelFailureDiagnostics`，区分认证、额度、限流、请求拒绝、上下文上限、服务器错误、超时、传输及响应流中断。
