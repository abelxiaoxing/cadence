## Architecture and exact outputs

All new executable code lives under scripts/host-prototype/ and is not imported by src. It is not shipped as a supported backend. No public runtime command or mode is added.

Task prep-build owns protocol.mjs, build.mjs and windows-launcher.c. protocol.mjs defines a closed bounded request/observation schema with protocol version, absolute executable, argv, cwd, explicit environment, execution/shutdown deadlines and output limits; reject mounts, NUL, invalid/relative paths, duplicate case-insensitive Windows environment keys and unknown fields. Separate root exit, managed settlement, descendants-reaped-in-declared-scope and termination-unconfirmed. Never encode an infrastructure failure as a product Red verdict. No state/apply callback or consumer root authority is passed.

build.mjs exposes testable pure build-plan/manifest validation helpers and a guarded direct CLI: node scripts/host-prototype/build.mjs --output <explicit-directory>. Windows x64 only; resolve the installed compiler/SDK explicitly, use shell-free spawn and validated argv; fail unavailable with bounded diagnostic on Linux/wrong architecture/missing compiler. It never downloads or compiles implicitly when imported or during normal package execution. The recipe selects installed Visual Studio 2022 Build Tools/MSVC x64 through its explicit environment, records exact compiler/SDK identity and checks supported versions. CI host image is pinned by label and tool versions are recorded; no claim that hosted-image contents are immutable. Source SHA256, output SHA256, architecture and recipe/protocol version are written only after successful build. Reject stale source/tampered/wrong-arch output. Native PE is a CI build artifact, never a text/Base64 Worker submission.

windows-launcher.c is a small experimental C source using Win32 APIs, no third-party runtime dependency. Create/configure Job (kill-on-close, no permitted breakaway), completion observation, and minimal inherited handle set; create target suspended, assign to Job then resume. Job/assignment failure must not execute target instructions. Watch control EOF, deadlines and cancellation, distinguish root exit from Job-empty and retain uncertainty. Children cannot inherit the controlling Job handle. Bounded command protocol and Unicode-safe argv construction must be documented/tested. The source is NOT called production-ready because Linux source assertions see API names; actual ordering/handle behavior is exercised only on Windows.

Task prep-harness owns macos-supervisor.mjs, lifecycle-fixture.mjs and qualify.mjs. The macOS prototype uses Node separate process groups and an EOF monitor sufficient to test host-loss handling, TERM/KILL deadlines and group-settlement observations. Active setsid/daemonize/deliberate group escape is explicitly unsupported; helper kill is not a guarantee of arbitrary descendant cleanup. Do not pretend parent PID alone identifies owned processes after reopen. Prototype fixtures operate only on generated temporary roots and their own processes; bounded cleanup or an uncertainty result is mandatory.

qualify.mjs exposes local-testable result validation/case planning, and CLI node scripts/host-prototype/qualify.mjs --require-native --output <explicit-directory> [--helper <explicit-Windows-helper>]. Native invocation checks actual platform/architecture/Node, Windows helper manifest and hashes, executes all required cases, and writes a success manifest only after actual successful native execution. Wrong platform, missing compiler/helper, timeout, unconfirmed termination or invalid result fail nonzero (not skip). Imports do not launch tests/builds. No test-only fake platform or process adapter is accepted through the public CLI; injected adapters are confined to unit tests and cannot generate a native-qualified result.

Required native cases: assignment failure with zero command side effect; root exiting while descendant remains; output/witness streaming and limits; cancellation/timeout; parent/control-channel loss; helper failure; Unicode/spaced cwd/executable/arguments; explicit system environment without credential dump. macOS cases qualify only process-group scope and record deliberate-detach limitations. Reports identify OS build, architecture, actual Node/compiler versions, source/protocol/helper hashes, case counts and individual outcomes, never environment values or secrets. Complete/failed/uncertain have separate outcomes. No success report from mere file presence, source matching or passing mock tests.

Task prep-ci owns additions to ci.yml, docs/host-trusted-preparation.md and test/host-prototype-ci.test.ts. Add a distinct prototype job (not general workflow execution) with Node 22.13.0/24.13.0, Windows x64 and macOS x64/arm64 lanes, using explicit runner labels (Windows 2022, Intel macOS 15 and macOS 15 arm64 where available). Assert actual platform and arch before execution; label availability remains a CI environment condition, never silent architecture substitution. Set up installed MSVC tools via existing runner facilities and shell-free Node build script; no new action/runtime dependency needed beyond existing checkout/setup-node/setup-bun and an ordinary artifact upload action. Use read-only repository permissions, no secrets on fork PRs, unique bounded artifacts per matrix cell, record commit/source identity and retain failure logs without labelling them success. Compile only in explicit native job; no install/postinstall hook, no runtime downloader, no automatic publish. Existing Linux/OpenSpec/storage jobs remain byte-preserved except necessary additive layout.

Native CI executes build then qualify as direct Node CLI steps. Uploading diagnostics on failure must not override job failure. Do not add this require-native command to the local sealed full-suite verifier. The local CI contract test asserts matrix commands/versions/arch checks, no production activation or package hook, and a clear docs boundary. Existing tarball tests establish no prototype assets accidentally ship. Future release packaging will consume verified native build outputs in an explicit staging directory and update its member manifest in the later integration delivery, not this one.

The parent handles bounded implementation choices within this approved preparation scope without reopening the stage split.
