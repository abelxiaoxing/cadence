## Why

Implement already schedules independent Workers and projects parent-owned recovery, but the host relies on prompt compliance to keep the parent running. A premature final response strands actionable work until the user asks to continue. Design also presents initial phase permissions without directly presenting the wider accepted recovery policy.

## What Changes

- Present the accepted recovery policy and decision ownership during Design preflight, and resolve known substantive decisions and external prerequisites there.
- Continue an explicitly activated Implement goal through host-scheduled parent turns while current control-plane evidence supplies an actionable next step.
- Project bounded recovery guidance for known recoverable failures; preserve authority, verification, cancellation, and consumed budgets.
- Prevent repeated unchanged status or failed operations from manufacturing progress.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `abel-workflow-prompt-package`: Design recovery handoff and host-owned Implement continuation.
- `workflow-run-control-plane`: Evidence-bound investigation, conditional retries, and technical amendment after correction exhaustion.

## Impact

Changes affect Design summaries and guidance, the Pi extension lifecycle, and recovery status projection. Existing sealed deliveries remain readable. Product completion still requires verified tasks, cumulative checks, currentness, transactional apply, post-apply verification, and settled operations. No new dependency or public slash command is introduced.
