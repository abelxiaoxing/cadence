## Required behavior

- **LW-R1 — Explicit terminal workflow.** One `/cadence` entry supports New/Open, code/research/diagnosis, planning, execution, checks, review and history. `/cadence <request>` may prefill a new goal, not start work. Ordinary/quoted/model-generated/replayed input, startup, nonterminal modes and child processes do not run tasks. Opening history never executes or resumes work.
- **LW-R2 — Human workflow consent.** Code tasks require a readable plan and a current explicit terminal Start confirmation. Users can edit the plan and explicitly Continue after failure/interruption. Research/diagnosis use readonly agent tools and human review of conclusions; they cannot silently escalate to editing. Consent is not certification of future code bytes or an unbreakable sandbox.
- **LW-R3 — One ordinary editing agent.** Use the current Pi model/provider and publicly resolved request authentication, without silent model/provider fallback or credential files/argv/logs. One Cadence-owned run per checkout edits the chosen working copy through standard host tools. Preserve useful package-owned role instructions and bounded project context. No candidate sealing, custom graph scheduler, transaction apply, hidden retry or background continuation after departure.
- **LW-R4 — Real checks and honest review.** Parent-run commands explicitly confirmed in the terminal record command, cwd, exit, duration and bounded output. Worker prose/process exit is not a passing check. Show staged/unstaged/untracked/binary/deletion changes and pre-existing dirt without attributing all changes to Cadence. Support bounded non-Git change inventory honestly. Changes after checking/review invalidate freshness. Human review can close a task with visible unresolved/unrun checks, but cannot convert them to passed or certified.
- **LW-R5 — Simple durable context.** Persist small human-readable task/plan/result/activity records under a distinct new project namespace; keep raw diagnostic output/coordination private. Unknown/corrupt/linked/oversized state refuses without reset. Missing state remains absent on list/doctor/open. Reopen restores context and exposes interrupted work; it does not import old approval, reconstruct exact execution or replay writes.
- **LW-R6 — Bounded operational cancellation.** Foreground progress remains cancellable. Navigation/shutdown aborts owned work and waits within explicit bounds. Observed direct-child close is not proof that every escaped descendant stopped. Unconfirmed stop is interrupted/unknown, not success, and keeps the new coordination lock. Only explicit informed recovery of a stale new lock may permit another run; never clear old runtime locks or delete consumer material. Concurrent external editors remain outside Cadence's coordination guarantee.
- **LW-R7 — Actual retirement and independence.** Remove the certified runtime from source, default tests, shipped members and generated consumers; do not hide it behind a thin new UI or ship two executors. Retain independent research/commit skills, configuration loading/missing-only install template, Agent licensing/pins and startup presentation. Classify old test assertions as retained/ported/superseded before deletion. No automatic Git mutation, external software installation, destructive cleanup or publication.
- **LW-R8 — Maintainable qualification.** Tests distinguish fast controller logic from real SDK/process/filesystem/package/terminal integration. Keep real archive member/body/pin audits and source/extracted production checks. Observe actual Node/Pi/platform identities without release version predicates; dependency metadata/locks remain separate. Local stubs/loopback model tests do not become paid-provider, physical-human or unexecuted platform evidence.
