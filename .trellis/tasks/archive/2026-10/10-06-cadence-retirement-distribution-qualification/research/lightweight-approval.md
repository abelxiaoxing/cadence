## Main technical choices

Use existing owner names with small rewritten bodies and one SDK child; no second execution framework. New project namespace `.cadence/assistant/tasks` and private `cadence-assistant-v1` avoid old stores. One small coordination lock and atomic single-record metadata are ordinary bookkeeping, not multi-file transaction guarantees. Freshness checks concern the displayed project changes/check commands at workflow boundaries, not every low-level I/O or executable image.

Public resolved parent request auth is transferable through an anonymous pipe into an in-memory SDK runtime. The earlier research claim that ephemeral auth necessarily lacks a host API was corrected in `lightweight-auth-runner-decision.md`. Avoid CLI main because its startup housekeeping can migrate/clean user resources. The native-provider snapshot resolver needs actual synthetic wire tests; prior ordinary-key proof alone does not qualify every auth/API variant.

Package/role/native bounds remain small. Standard editing tools are trusted tools, not a sandbox; controller code never inserts commit/install/reset/publish actions. Parent checks are explicitly confirmed commands, not model-generated PASS. New integration budgets are declared separately; old5000-ms failures remain historical failures, not retimed passes.
