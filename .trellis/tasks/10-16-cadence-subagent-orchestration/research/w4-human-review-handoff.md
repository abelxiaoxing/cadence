## 2. Concrete APIs and Ownership

- `TaskActions.observe(review)` produces the actual preview; `activate` synchronously registers metadata work with the existing accepted-work original before its first effect.
- `TaskScheduler.reviewBarrier(operationId): Promise<ReviewBarrier>` joins the existing ordered checkout gate.
  `ReviewBarrier.assertHeld()` checks real ownership/holding/liveness; `release()` refuses outstanding original writes or recording quarantine.
  Metadata is neither an episode nor a child/check reservation.
- `HistoryWriter.bindReviewContext(source: ReviewContextSource)` installs one actual owner callback, refusing replacement.
  `ReviewContextSource(taskId, published?)` returns real observation/current obligations; `published` is only the writer's exact own candidate after its actual save.
- `HistoryWriter.reviewOutput(operationId)` validates committed review metadata and registers its effect checks.
  Content keeps historical run association but new artifact storage belongs to the metadata operation, without allocating or borrowing the old episode reservation.
- `currentChecks(files,taskId,configured,current,snapshotSeq?)` is shared by `HistoryProjection.checkObligations` and TaskActions review.
- `HistoryReader.publishedPlan(taskId,snapshotSeq,current?)` optionally proves the current raw revision/identity/plan through cold original publication lineage.
  `TaskPublicationLineage` uses the same `publicationTransition` as existing operation/run receipts.
- `HistoryReader.reviewRun(taskId,runId,snapshotSeq)` validates the latest non-check execution and its actual drained/published RunState.
  Task-scope discovery is followed by run-scope reduction, since task indexes do not contain every auth/process row.
- `HistoryFiles.append(...,beforeEffect?)` carries the writer's narrow review guard across actual asynchronous file-open/stat and pre-body/pre-marker boundaries.
  Existing callers and all original read/capture/native ceilings remain unchanged.

## 3. Contracts

Preview binds actual raw task revision/identity, saved graph identity/revision, explicit selected run, current model/cwd/environment/checkout observation, check revision and issue acknowledgment.
The existing grant engine rejects mismatched targets/versions or missing acknowledgment.
The review target is the latest actual non-check execution, not a successful older run selected to hide a newer failure.

No checkout barrier exists during the human confirmation interval.
After acceptance, the bounded metadata waiter shares writer preference/order and the same holder exclusion as children/checks.
Younger readers/writers cannot pass a held review barrier; review does not consume one of the two native reservation slots.
Stop closes queued barriers and accepted-work tracks the original metadata continuation separately from native/auth/storage originals.
Unknown reporting never refunds a barrier or authorizes late publication.

The real callback rechecks owner/source/model/cwd/environment identity, selected raw task bytes, control/checkout generation, actual business changes, definitions/current check revision and original saved-plan/run proofs.
It is invoked before retention/publication effects, after relevant awaits and before/after journal commitment.
The only allowed task-byte transition is the writer's own exact publication candidate; it does not normalize external edits.
Access rotation does not itself cancel already accepted review.

Current obligations use the latest exact definition result and epoch/cwd/environment/checkout freshness.
Superseded failures remain immutable history rather than permanently poisoning review.
Removed/changed configured definitions remain historical; a currently configured unmatched definition is not-run.
Latest manual selections participate in code-review issues.
No real current check means a code-check issue; legacy summaries are not fresh service PASS.
Readonly task review has no fabricated code-check obligation.
Incomplete observation/capture, noncompleted selected execution and current failed/canceled/stale/unrun checks require acknowledgment.
Agent review remains advisory.

Changes/review text are actual committed owner content, searchable and exportable under the selected historical run.
Changes remain bounded128KiB; review context has a finite512KiB input ceiling to accommodate exact bounded obligations, with pre-copy owner queue reservations and unchanged1MiB encoded input/32MiB detail limits.
Only writer-returned committed references are used.
Done changes no child/check/native/recording/parent settlement; strict v1 publication preserves its current result/check summaries and adds the human review.

Cold graph proof follows the latest accepted Save plus each subsequent exact expected-to-observed publication chain, preserving graph and readable plan.
There is no RAM publication cache to evict and no all-archive graph cache.
Pending/conflicted/uncertain later operations, missing links, external raw bytes or exhausted proof budgets refuse.
Historical model/source IDs still need explicit fresh rebind/Save before a future Start; review imports no execution approval.
