# Main Decision — Explicit Choice and Actual Current Views

Adopt the source-backed recommendation in `model-current-view-composition.md`, with the accepted parent scope and existing limits controlling implementation.
This is a technical composition decision under continuous approval, not a new provider/profile product or scope reduction.

- Each explicit service boot starts with one loaded public ModelRuntime and no selected model.
  History/current readonly data can be available without mutation authority.
  No first-model fallback, settings locks/writes, session-derived implicit choice, auth probe/getAuth or credential/configuration migration.
- Add finite authenticated native/browser catalog and explicit owner choice using actual installed getModels/getModel/getSupportedThinkingLevels and existing select validation.
  Keep current exact one-model/thinking inheritance across assignments.
  SDK max is visibly unsupported by the current Cadence codec, never clamped to xhigh.
- Catalog enumerates only bounded credential-free candidates from actual configured sources, with explicit capacity/unsupported states.
  Prefer deterministic bounded paging when needed; never present a clipped first page as complete.
  An explicit exact selector can be validated without an auth probe.
  Catalog reads do not select or allocate execution authority.
- Choice is epoch RAM state; no host-config schema rewrite.
  Install synchronously after final source/version/access and comprehensive busy checks.
  Any queued/original/accepted/native/auth/storage/metadata/review/check work or quarantine refuses a change.
  Success advances a real config revision/catalog identity and invalidates unused grants; accepted work is never retargeted/canceled.
  Reuse exact current choice when appropriate; retire only unused quiescent RAM selections, not history or credentials.
- Use the replayed revision floor, fresh epoch/cwd identity and actual frozen check environment, not hardcoded cross-boot authority.
  One TaskActions uses narrow real dependencies and a nullable choice accessor; do not reconstruct action owners on choice changes or cast incomplete ServiceHost objects.
- Supply finite shared current/changes/model/choice DTOs and discoverable bounded active-run refs, alongside existing history/progress/readers.
  Current v1 text is labeled current-v1, not a forged private ContentRef.
  Saved graph ref joins actual publication lineage and uses the existing graph reader for bodies.
  Inconclusive remains unavailable/progress, never absent; no old model IDs/approvals refreshed on read.
- Bind W6's actual metadata adapter and an explicit model chooser.
  Proposal UUID/hash is prospective local metadata through one portable helper; real Save still requires its own preview/confirmation/retention/publication.
  No automatic Generate acceptance or mutation replay.
  Same-attachment capability/current refresh must not allocate a second hidden session or keep a stale no-selection capability forever.

Compose actual package-relative assets and independently computed service contract identity with the existing local browser build identity.
Normal mutation ingress as well as UI must reject genuine incompatibility; do not echo the server identity as the client's proof.
Compatible explicit Cancel remains a separately authenticated safety path.
Compiled service cannot read/execute TypeScript/source-tree fallbacks; source test factories must receive or derive a real source-bound identity explicitly.

The action paths are now implemented and independently reviewed in the core, but host admission remains null until the real choice/current/asset/build/lifetime ports are fully composed and exercised.
Then qualify actual authenticated full workflows before claiming an accepting host; no fixture defaults or unsupported named methods may admit work.
W1 proxy/recovery, W5 native cutover, full W6 workflow and W7 distribution remain mandatory distinct gates.
