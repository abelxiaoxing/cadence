# Lightweight Distribution and Retirement

## Actual shipped surface

`provenance/package-members.json` specifies the complete **129 regular members / 35 runtime source files** candidate for independent final review.
It was selected from native runtime imports, maintained worker imports, generated executables and exact asset/font/license closure, never the tarball under test.
The old34/16 policy is superseded, not silently used to qualify new bytes.
`package.json` exposes only `./src/index.ts` as the Pi extension and `./skills` as independent skills; no prompt aliases, task RPC/tool or second executor.
Members include three fixed Agents, research/check examples, MIT license and pi-subagents notices/license.
Tests, build scripts, repository provenance metadata, Trellis files, private diagnostics and retired helpers do not ship.
Concise usage/reuse docs, complete notices and prebuilt `web/dist` do ship.

`scripts/package-audit.mjs` checks safe regular tar members, uniqueness, checksums, exact membership, every body against reviewed source and all Agent provenance hashes.
It rejects traversal/control/ambiguous names, link/special/extended types, source links, duplicate manifest entries, drift and pin mismatch before extraction.
A count/listing alone cannot replace this audit.
`scripts/pack-check.mjs` performs a real `bun pm pack`; retain a separate real-pack route for qualification too.

## Canonical executable paths

`scripts/build-operator.mjs` builds the generated readonly `src/operator-cli.mjs` from `operator-cli-entry.mjs` and local dependencies; `--check` compares exact generated bytes.
`src/sdk-worker.mjs` is maintained ordinary JavaScript and runs against installed peers, with no TypeScript/source-tree fallback or CLI startup.
Pi itself loads the extension TypeScript.
Extracted fixtures use actual package bodies in node_modules layout and trusted existing peer links, not package-manager installation or automatic downloads.
Cadence declares mandatory public `undici: ^8.9.0` as its own peer and pins development8.9.0, reusing the SDK's existing resolution; Pi peers remain wildcards.
The approved in-progress redesign now adds exact `ws: 8.21.3` as the sole production dependency and25 exact development edges for browser/build/qualification families.
Pi development pins remain0.84.3; dependency availability/installation is not evidence of service/browser integration.
Its public dispatcher API is used by the dedicated configured-proxy owner and ephemeral workers after SDK/adapter imports, never through a private Pi HTTP subpath or an incidental ancestor/transitive dependency.
Source/extracted fixture host package roots are `@earendil-works`, `typebox`, `undici`, plus production `ws`; qualification identity capsules bind coding-agent/AI/TUI/agent-core/typebox/Undici separately (six identities).
Trusted public package-store files can legitimately have nlink2; owned source/archive/receipt single-link checks must not be relaxed to accommodate them.
Cadence now declares the approved Node baseline `>=22.19.0`, matching reviewed Undici8.9.0 and SDK0.84.3 requirements.
This metadata change is not proof that all eligible runtimes, especially Node22, were executed.
Dependency-edge lock generation must be standard Bun lockfile-only, lifecycle-disabled and externally offline, with isolated HOME/config/temp/cache and trusted existing cache copies when needed; preserve failures/preimages and stop rather than fall back online.
Explicitly authorized online cache/license preparation is a separate step, never an implicit fallback of the offline command.
`--prefer-offline` is not network isolation: use an actual network namespace and retain its capability/route observation.
Bun's range metadata may expire despite cached package bodies; record failures and request/perform only separately authorized preparation before a new isolated attempt.
Capture package/lock hashes before spawn and after exit; preserve original identity/integrity tuples and review alias placement rather than hand-editing the generated lock.
Root dependency setup likewise uses `--frozen-lockfile --ignore-scripts`, clean HOME/config, externally disabled network and verified cache, not copied temporary node_modules or lifecycle execution.
An external dependency tar's narrowly reviewed identical-body duplicate member is not permission to relax Cadence's own strict archive policy.
Body audits bind every current runtime and asset; matching counts never imply unchanged bytes.
Archive validation alone does not prove that tar extraction or later copying produced a usable installed tree.
`test/distribution.test.mjs` audits each extracted/copied/post-peer tree with `auditPackage(archive, treeRoot, expected, provenanceRepoRoot)` and refuses linked roots/ancestors before inspecting members.
Its filtered `cpSync` traversal copies only extracted archive bytes while avoiding documented Unicode-sensitive native-copy paths; the first Windows missing-file cause remains unproven until native evidence identifies it.
Never fill an installed gap from repository source, simplify the hostile Unicode/space/percent/bang path, or let a missing entrypoint satisfy the corrupt-config refusal test.
That negative requires the actual fixed `operator-refused` JSON stderr as well as unchanged bytes and exit 1.
Bounded failure-safe distribution diagnostics record stage/body hashes/first gap under the fresh owned fixture, not raw environment or credential material.

Operator interface:

```text
node <cadence>/src/operator-cli.mjs doctor|runs [workspace]
```

Default command is doctor; default workspace is cwd; extra/unknown arguments refuse with fixed `operator-refused` JSON and exit 1.
`inspectConsumer` returns schema `cadence-assistant-doctor/1`, root/cwd, task count, check name/timeout list, `checkStatus: "not-run"`, coordination and an observation notice.
`inspectRuns` returns `cadence-assistant-history/1`, bounded task summaries, historical check metadata/review and running-as-interrupted projection.
Neither invokes controller/runner, recovery, migration, Git mutation or installation; absent stores stay absent.
Stored statuses are not revalidated check freshness.

Do not retain them behind new UI or copy them into generated bodies.

Retained/ported intent and superseded mechanisms have explicit dispositions in task research; fewer tests alone prove nothing.
Historical **5547 passed / 5 failed / 9 skipped remains FAILED/SUPERSEDED**, never a new pass.
Old preimages/reports and [pre-refresh specs](../../tasks/archive/2026-10/10-06-cadence-retirement-distribution-qualification/research/retired-certified-specs/manifest.json) remain historical evidence.

Only the explicitly confirmed new stale-lock recovery described in [storage](./database-guidelines.md) exists.
